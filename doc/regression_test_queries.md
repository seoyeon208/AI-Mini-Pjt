# 수동 회귀 확인용 질문

현재 v2의 요청 분류와 조사 대상 검증을 확인한다. 모델 응답에 따라 결과가 달라질 수 있다.
자동 회귀 테스트는 `tests/`에서 실행한다.

| 질문 | 확인할 동작 |
|---|---|
| payments-service 결제 응답이 느려지고 CPU가 치솟았어요, 원인 확인해주세요 | payments-service를 조사하며 다른 서비스로 대체하지 않음 |
| cache-service 메모리 사용률이 계속 올라가고 있어요 | cache-service 상태 조회와 관련 매뉴얼 검색 |
| log-service 디스크 공간이 부족하다는 알림이 왔어요 | log-service 상태 조회와 관련 매뉴얼 검색 |
| gateway-service에서 payments-service로 가는 요청이 타임아웃 나고 있어요 | 두 서비스 모두 조사 대상에 포함 |
| web-01 CPU 급증, auth-service 커넥션 풀도 같이 확인해줘 | 두 서비스 모두 조사하며 중복 작업 제외 |
| payments-service랑 cache-service 둘 다 저하됐는데 공통 원인이 있는지 분석해줘 | 복합 경로에서 상태 수집 후 비교 분석 |
| 로그인 응답이 느려요, 원인 확인해주세요 | 시스템명 입력을 요청하고 조사 중단 |
| billing-service 응답이 느려요 | 미등록 서비스 안내 후 조사 중단 |
| 안녕, 너는 누구야? | 일반 대화 경로, 운영 자료 조회 없음 |
| 제 이름은 민수입니다. 다음 메시지: 제 이름이 뭐였죠? | 같은 thread_id의 이력을 사용. 동일 DB로 재시작한 뒤에도 이력 유지 |

웹에서 서비스를 선택한 상태라면 해당 ID가 요청에 추가된다. 대상 누락 사례를 확인할 때는 서비스 선택을 해제한다.
