# 조회 답변 개선 평가 — 2026-10-21

상태 조회는 원본 관측값, 매뉴얼 조회는 원문의 번호별 절차를 그대로 제공하도록 바꿨다.
실제 모델 평가에서 조회 6건 모두 원본 대조를 통과했다. 복합 진단 3건은 여전히 검증에 실패했다.
따라서 이번 결과는 **조회 경로의 정확한 정보 전달과 응답 시간 개선**에 한정된다.

## 구현 변경

- LangGraph의 분류·게이트·조사·작성·검증·최종 출력 단계는 유지했다.
- 단순 조회의 작성 단계는 원본 데이터로 답변을 구성한다. 원인 추정이나 요청하지 않은 조치를 추가하지 않는다.
- 매뉴얼 조회는 실시간 모니터링 없이도 원문의 절차·조건·순서·출처를 제공한다.
- 조회 검증은 원본과의 대조(`source_exact`)이며 LLM 채점 결과를 만들지 않는다. 화면에도 원문 기반 답변으로 표시한다.
- 복합 진단은 코드 사실 검사와 8B 모델의 의미 검수(`facts_and_llm`)를 유지한다. 반려 시 최대 1회 재작성한다.
- 출처에 있는 수치의 반복은 허용한다. `78`과 `78.0`은 같은 값으로 처리하며, `190%`가 있다는 이유로 `90%`를 허용하던 부분 문자열 비교도 제거했다.
- 자유 서술의 시스템·지표 뒤바꿈과 임계값 오용은 LLM이 의미를 검수한다. 코드의 수치 존재 확인만으로 이러한 오류가 방지된다고 보장하지 않는다.

## 비교 조건과 결과

이전 결과 [after.json](after.json)과 현재 결과 [answer-quality.json](answer-quality.json)을 비교했다.
분류 모델 `qwen3.5:2b`(`think=false`)와 복합 진단 모델 `qwen3:8b`는 같다.
질문 15개, 모니터링 고정값, 매뉴얼 원문도 동일하다. 실제 로컬 Ollama·LangGraph·MCP를 사용했고,
인위적인 첫 호출 실패와 외부 추적 전송은 껐다. 각 질문은 빈 이력으로 1회씩 실행했다.

| 항목 | 이전 | 현재 |
|---|---:|---:|
| 실행 오류 없이 완료 | 15/15 | 15/15 |
| 경로·대상 범위·대상 확인 처리 일치 | 15/15 | 15/15 |
| 상태 조회 중앙값 | 7.620초 | 0.994초 |
| 매뉴얼 조회 중앙값 | 10.368초 | 1.154초 |
| 조회 6건 중 재작성 발생 | 6/6 | 0/6 |
| 상태 조회 검증 통과 | 0/3, 코드+LLM | 3/3, 원본 대조 |
| 매뉴얼 조회 검증 통과 | 1/3, 코드+LLM | 3/3, 원본 대조 |
| 복합 진단 검증 통과 | 0/3 | 0/3 |
| 복합 진단 중앙값 | 97.845초 | 154.966초 |

상태 조회 중앙값은 약 87.0%, 매뉴얼 조회는 약 88.9% 감소했다.
조회에서 LLM 작성·검수 호출을 없앤 결과이며, 모델 자체의 추론 속도가 향상된 것은 아니다.
각 유형 3개 질문을 1회씩 실행한 소규모 측정이므로 모든 요청에 같은 개선율을 보장하지 않는다.
이전에는 실패 답변도 시간에 포함됐고 현재는 검증 방식이 달라졌으므로, 통과율을 LLM 정확도 향상으로 비교하지 않는다.

답변 내용도 별도로 확인했다. 상태 조회는 원본 수치를 유지하고 추정 원인·조치를 추가하지 않았다.
메모리 누수 5개, DB 장애 3개, 디스크 부족 5개 절차가 조건과 출처를 포함해 전달됐다.
이전 DB 매뉴얼 답변은 자체 검증을 통과했지만 실제 절차를 제공하지 않았다.

## 남은 문제

- 복합 진단 3건 모두 최종 분석·조치가 공개되지 않고 확인된 관측값만 제공됐다. 이번 개선으로 복합 분석 품질까지 해결됐다고 볼 수 없다.
- 응답 지연 사례는 관련성이 낮은 DB 장애 문서까지 검색됐고, 검수 모델이 그 문서의 모든 절차를 요구했다.
- 두 서비스 관련성 분석에서는 추정에 불과한 인과관계를 단정하는 문장이 생성됐다. 검수에도 HTTP 504를 임계값으로 다루는 오류가 있었다.
- 메모리·디스크 비교에서는 디스크 95%가 90% 기준을 넘은 것을 '모순'으로 판단했다. 이 잘못된 검수 의견이 재작성에도 반영됐다.
- 복합 진단 시간은 이번 실행에서 증가했다. 서술 수치의 존재 검사를 통과한 뒤 실제 LLM 검수까지 진행한 영향과 생성 변동이 섞여 있어, 전체 서비스가 빨라졌다고 표현할 수 없다.
- 현재 매뉴얼 추출은 제공된 자료처럼 `1. ...` 형태로 절차가 한 줄씩 작성된 문서를 지원한다. 다른 문서 구조를 자동으로 이해하는 범용 파서는 아니다.

다음 개선 우선순위는 복합 진단의 관련 문서 선별과 검수 오류의 재작성 전파 방지다.
검증 기준을 낮추거나 실패 답변을 그대로 공개하는 방식은 적용하지 않았다.

## 재현 및 검증

추가로 [수치 의미 검수 결과](semantic-check.json)에 원본 증거를 고정한 3개 사례를 기록했다.
`qwen3:8b` 검수 모델은 CPU·메모리 뒤바꿈과 매뉴얼 기준값을 현재 CPU로 적은 오류를 모두 구체적으로 지적했다.
다만 올바른 수치 반복 사례도 추가 정보·설명 누락을 이유로 반려했다.
즉, 이 2개 오류를 찾아낸 것은 확인했지만 정상 답변의 과도한 반려는 해결되지 않았다.
이 검사는 의미 검수 자체를 확인하는 별도 실행이며 위 15개 질문의 시간 측정에 포함하지 않았다.
