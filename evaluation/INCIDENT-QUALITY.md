# 복합 진단 개선 기록 — 2026-10-21

이번 작업은 보완 순서 중 1번인 복합 진단을 대상으로 했다. 검색 잡음과 조치 조건 누락을 개선하고,
검수 의견의 형식·인용을 확인하도록 변경했다. **복합 진단 품질 전체가 해결된 상태는 아니다.**
최종 실제 모델 실행에서 복합 답변 3건 중 1건이 검증을 통과했다. 나머지 2건은 분석·조치를 숨기고 관측값만 제공했다.

## 적용한 변경

- BM25 후보는 제목·검색 키워드와도 겹쳐야 한다. 본문에 우연히 등장한 단어만으로 다른 장애 문서를 선택하지 않는다.
- 작성 모델은 조치 문장을 새로 쓰는 대신 문서 ID와 절차 번호를 선택한다. 코드는 실제 원문을 가져와 조건과 출처를 보존한다. 없는 문서·절차는 거부하고 중복 선택은 제거한다.
- 원문과 완전히 같은 조치는 코드로 대조하고 LLM 검수 입력에서 제외한다. 따라서 원문 일치는 확인되지만, 해당 조치가 현재 상황에서 최선인지까지 평가한 것은 아니다.
- 관측 필드·수치·출처를 검사한 뒤 LLM이 자유 서술의 모순과 근거 없는 단정을 검토한다. 검수 결과는 유효 여부와 오류 유형·초안 인용·출처·원문 인용·이유로 받는다.
- 검수 의견의 인용이 실제 초안과 원문에 없거나 형식이 잘못되면 재작성에 전달하지 않는다. 유효한 지적에만 최대 1회 재작성을 허용하며, 실패한 초안은 공개하지 않는다.
- 작성·검수 지침에 미확인 지표를 정상이라고 단정하지 않도록 명시했다. 프롬프트 지침만으로 모든 오류를 방지한다고 보장하지 않는다.
- 기존 LangGraph 흐름과 공개 보고서 API는 유지했다. 새로운 의존성은 추가하지 않았다.

## 검증 기준 변경

이전의 관련성·완전성·명료성·도메인 적합성 4개 점수에서 모두 4점 이상을 요구하는 방식은 제거했다.
현재 실행 중 검수는 사실성에 집중한다. 완전성·유용성까지 평가하는 품질 점수와 같지 않다.
`validation_scores`는 기존 API 호환을 위해 빈 객체로 남겼다.

로컬 분석·작성은 `qwen3:8b`, 검수는 `qwen3.5:2b`의 `think=false`를 사용한다.
OpenAI 경로는 기존 quality 모델을 유지한다. 모델과 판정 기준이 모두 달라졌으므로 통과율 차이를
동일 기준에서 측정한 모델 정확도 향상으로 표현하면 안 된다. 인용이 일치해도 검수 논리까지 맞는 것은 아니다.

실패한 답변의 원문 조치까지 공개한 것으로 계산하지 않는다.

## 답변을 읽고 확인한 남은 문제

- 응답 지연: 검수 모델이 타당한 자료 부족 설명을 오류로 판단했다. 초안에는 측정값 92%를 '92% 초과'로 표현한 부정확함도 있었다. 따라서 이 사례를 단순히 정상 답변의 오탐만으로 해석하지 않는다.
- 서비스 관련성: 직접 인과관계를 확정하지 않고 가설과 미확인 사항을 구분했다. 다만 CPU 91%를 '91% 초과'로 표현한 부분은 검수를 통과했다. 자체 검증 통과가 모든 문장의 정확성을 보장하지 않는 사례다.
- 메모리·디스크: 앞선 실행의 '디스크 문제 없음' 표현은 최종 초안에서 사라졌다. 그러나 검수 모델이 원문에 공백을 삽입해 인용 일치 검사에 실패했고, 그 의견을 재작성에 전달하지 않은 채 진단 공개를 차단했다.
- 코드 검사는 정형 필드와 수치 존재를 확인한다. 자연어의 초과·이상, 가설·단정, 근거 없는 정상 판정 등은 여전히 의미 검수에 한계가 있다.

다음 보완 대상은 이 검수 오탐과 의미 오류 누락이다. 검색과 원문 조치 보존은 적용했지만,
복합 진단을 완료 항목으로 처리하거나 새 기능으로 우선순위를 넘기기에는 이 문제가 남아 있다.

## 정상·오류 대조 7개

[별도 검수 결과](incident-semantic-check.json)에 정상 수치 반복, 원문 조건 보존과 5종 오류를 기록했다.
정상 2건은 허용했고 오류 5건은 차단했다. **이를 의미 오류 탐지 정확도 100%라고 해석하면 안 된다.**
오류 5건 모두 검수 인용이 초안 또는 근거와 일치하지 않아 형식·인용 검사에서 차단됐다.

| 사례 | 기대 | 결과 | 확인된 한계 |
|---|---|---|---|
| 올바른 수치 반복 | 허용 | 허용 | 이 한 사례에서 정상 처리 |
| 원문 조건을 보존한 조치 | 허용 | 허용 | 원문 조치는 코드 대조로 처리 |
| CPU·메모리 뒤바꿈 | 차단 | 차단 | 지표 오류는 지적했지만 인용에 공백을 추가 |
| 임계값을 현재 측정값으로 사용 | 차단 | 차단 | 수치 오류는 지적했지만 인용이 달라 재작성 불가 |
| 배포 오류를 원인으로 단정 | 차단 | 차단 | 단정 근거 부족은 지적했지만 초안 인용 불일치 |
| 조건을 삭제한 조치 | 차단 | 차단 | 실제 조건 누락 대신 정상 수치를 잘못 지적 |
| 미확인 디스크를 정상으로 단정 | 차단 | 차단 | 미확인 상태 단정은 지적했지만 근거 인용을 잘못 생성 |

차단 동작은 확인했지만, 정확한 지적과 인용을 반환해 답변을 제대로 수정하게 하는 검수기는 아직 안정적이지 않다.

## 재현과 범위

- 실행 방법: [평가 안내](README.md).
- 회귀 테스트: `python -m unittest discover -s tests -q` — 68개 통과(4.119초). HTTP/SSE·실제 MCP 연결과 근거 검사, 원문 조치 선택, 재작성 제한을 포함한다.
- 최종 평가 JSON에 기록한 주요 코드 해시와 현재 코드가 일치함을 확인했다.
- 고정 질문 SHA-256: `6252a634c8a6931d9dc602bc926030f0631b8a7eee00c8fd14c995d5108050cb`.
- 현재 절차 추출은 제공된 매뉴얼처럼 번호별 내용이 한 줄인 형식에 한정된다. 원문 자체의 품질이나 운영상 실행 적절성을 보장하지 않는다.
- 실제 OpenAI 호출과 운영 서버 데이터는 검증하지 않았다. MCP 동시 실행·SSE 오류 처리·LangSmith 평가·ADR은 이번 변경 범위에 포함하지 않았다.
