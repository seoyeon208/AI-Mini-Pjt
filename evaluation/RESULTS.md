# 실제 모델 평가 결과

2026-10-20에 같은 질문 15개를 변경 전후 각각 1회 실행했다. 원본은 `before.json`, `after.json`, 질문과 기대 조건은 `cases.json`에 저장했다.

## 적용한 변경

빠른 모델을 `qwen3:0.6b`에서 `qwen3.5:2b`로 변경하고 `think=false`를 지정했다. 분석용 `qwen3:8b`, 조사 흐름, 검색 로직과 검증 기준은 유지했다. 기존 모델에서 추론 모드만 끄는 실험은 개선되지 않아 채택하지 않았다.

## 측정 결과

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 분류 출력 형식 오류 | 10/15건 | 0/15건 |
| 기대 경로·대상 확인 처리 충족 | 9/15건 | 15/15건 |
| 상태 조회 3개의 응답 시간 중앙값 | 79.054초 | 7.620초 |
| 매뉴얼 조회 3개의 기대 문서 확보 | 0/3건 | 3/3건 |

경로 조건 충족은 답변 정답률이 아니다. 응답 시간에는 검증 실패 후 확인된 자료만 반환하는 경우도 포함한다. 매뉴얼 확보 개선은 분류 경로가 정상화된 결과이며, 검색 알고리즘 자체의 개선 수치는 아니다.

| 상태 조회 질문 | 변경 전 | 변경 후 |
|---|---:|---:|
| auth-service CPU·메모리 | 109.763초 | 8.300초 |
| web-01 상태 | 79.054초 | 5.930초 |
| cache-service 메모리 | 6.331초 | 7.620초 |

앞의 두 질문은 잘못된 복합 분석 경로를 피하면서 시간이 줄었다. 원래 단순 조회로 처리되던 세 번째 질문은 오히려 느려졌다. 모든 요청의 속도가 개선됐다는 의미는 아니다.

## 남은 문제

- 변경 후 운영 요청 9개 중 자체 검증 통과는 DB 매뉴얼 요청 1개뿐이었다. 상태 조회 3개, 다른 매뉴얼 요청 2개, 복합 분석 3개는 모두 최종 검증에 실패했다.
- 실패한 초안에는 설명·한계 영역의 백분율 기재가 남아 있었다. 현재 검사는 관측 수치를 observations에만 적도록 요구하므로, 원본과 같은 수치를 반복한 경우도 반려한다. 일부 초안에는 단순 조회에 필요 없는 원인 추론도 포함됐다.
- 검증 실패 시 원본 관측값과 문서 출처는 제공하지만 분석·조치는 제외한다. 따라서 복합 진단 답변 품질이 해결된 상태는 아니다.
- 자체 검증을 통과한 DB 매뉴얼 답변도 직접 확인했을 때, 실시간 관측값이 없다는 이유로 절차 안내를 제한했다. 매뉴얼 조회는 실시간 관측값 없이도 원문의 절차를 안내해야 하므로 자체 검증 통과를 정답으로 간주하지 않았다.
- 응답 지연 검색에 DB 장애·네트워크 문서가 함께 반환되는 등 관련성이 약한 문서가 섞이는 문제는 남아 있다.

다음 우선순위는 조회·매뉴얼·진단별 답변 작성 지침을 구분하여 불필요한 추론과 검증 반려를 줄이는 것이다. 검증 기준을 낮춰 통과율만 높이는 방식은 적용하지 않았다.

## 측정 범위

Apple M5의 로컬 Ollama 모델과 실제 MCP를 사용했다. 모니터링 값은 고정하고 최초 타임아웃 연출은 껐다. 두 모델을 순서대로 사전 로드했지만 메모리 관리에 따른 재로드 시간은 응답 시간에 포함될 수 있다. 각 질문을 한 번씩 실행한 소규모 개발 평가이므로 일반적인 정확도나 반복 가능한 성능 보장 수치로 사용하면 안 된다. 재실행 방법은 [README](README.md)를 참고한다.
