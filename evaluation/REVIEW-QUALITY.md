# 문장별 검수 및 관측·가설 분리 — 2026-10-21

기존 복합 질문 3건과 표현을 바꾼 질문 3건에서 모두 분석·조치를 제공하고 검증을 통과했다.
정상·오류 대조 11건은 정상 5건 허용, 오류 6건 차단으로 기대 판정과 일치했다.
이는 고정 예시 데이터를 사용한 개발 평가이며 일반적인 모델 정확도 100%를 뜻하지 않는다.

## 수정 내용

- 검수 문장과 근거에 번호를 부여했다. 모델은 원문을 복사하지 않고 번호를 선택한다. 피드백 인용은 코드가 원문으로 구성한다.
- 모든 문장을 정확히 한 번 검토하도록 요구한다. 누락·중복·미등록 문장·근거 번호는 차단한다.
- 문장별 판정은 근거 있는 설명·가설·미확인 사항·모순·근거 없는 단정으로 나눈다. 판정 형식이 올바르다는 것과 의미 판단이 맞다는 것은 구분한다.
- 관측값·알림은 코드가 원문으로 표시하고, 모델은 근거가 있는 원인 후보와 확인할 자료를 선택한다. 가설에는 숫자와 퍼센트 기호를 허용하지 않아 측정값을 다시 쓰는 오류를 줄였다. 원본 수치·시간·인스턴스 식별자는 관측 영역과 출처에 남긴다.
- 확인할 자료는 로그·호출 추적·시계열 모니터링 등 10개 유형에서 선택한다. 이 항목으로 조건 없는 운영 조치가 섞이는 것을 막는다.
- 조치는 문서·절차 번호로 선택하고, 검증에서도 원문과의 완전 일치를 요구한다. 조건이 삭제되거나 문장이 바뀌면 코드가 차단한다.
- 명시적인 CPU·메모리 및 알림의 커넥션 풀·디스크 사용률은 실제 값과 비교한다. `초과·미만·이상·이하`를 구분하고, 복수 디스크 측정값을 한 값으로 합치지 않는다.
- 자료 없이 디스크를 정상으로 단정하는 명시적 표현을 차단한다. 코드 검사 후 남은 자유 서술을 모델이 검수한다.

기존 LangGraph 흐름, 최대 1회 재작성, 검증 실패 초안 비공개와 공개 보고서 API는 유지했다.
새 외부 의존성은 추가하지 않았다. 로컬 분석·작성은 `qwen3:8b`, 검수는 `qwen3.5:2b`(`think=false`)다.

실제 Ollama·LangGraph·MCP를 실행했다. 모니터링 응답은 기존 고정 예시 값으로 대체했고, 검색과 매뉴얼 원문은 실제 MCP 응답이다.
질문별 빈 이력, 모델 사전 로드, 인위적 첫 실패 비활성화, 외부 추적 비활성화 조건이다.

답변을 읽어 관측 알림과 가설이 구분되고, 가설에 측정 수치가 다시 생성되지 않으며, 확인 항목에 운영 조치가 들어가지 않는 것을 확인했다.
조치 원문은 총 16개가 보존됐다. 가설은 원인 확정이 아니며 추가 자료가 필요하다는 구조로 제공된다.

## 정상·오류 대조

[대조 결과](review-semantics.json)는 코드 검사부터 실행하고, 코드가 통과한 사례만 모델에 보낸다.

| 종류 | 결과 | 판정 근거 |
|---|---|---|
| 정상 수치 반복·조건 보존·가설·한계·올바른 기준 비교 5건 | 허용 | 코드 검사 및 모델 검수 |
| CPU·메모리 뒤바꿈 | 차단 | 시스템별 실제 지표 값 대조 |
| 기준값을 현재 CPU로 사용 | 차단 | 실제 CPU와 불일치 |
| 원문 조치의 조건 삭제 | 차단 | 조치 원문 불일치 |
| 미확인 디스크 정상 단정 | 차단 | 해당 관측 자료 없음 |
| 측정값과 같은 값을 '초과'라고 표현 | 차단 | 수치 비교 불일치 |
| 배포 오류를 원인으로 확정 | 차단 | 모델이 해당 문장의 근거 없는 단정을 지적 |

오류 6건 중 5건은 코드가 차단했다. 나머지 1건은 모델이 유효한 문장·근거 번호와 함께 단정 오류를 지적했다.
11건의 종합 판정 일치를 모델 단독 정확도로 표현하지 않는다. 모델이 정상 문장의 판정 이유를 부정확하게 서술하는 한계도 남아 있다.

## 실패 기록과 보완 이유

앞선 [6개 실행](review-quality.json)은 자체 검수를 모두 통과했지만, 사람이 읽고 확인한 결과 표현 변경 질문에 `92% 초과` 오류가 있었다.
커넥션 풀 수치 대조를 추가한 [해당 질문 재실행](review-recheck.json)에서도 재작성 후 오류가 반복되어 최종 진단이 차단됐다.
이 기록을 삭제하거나 통과로 바꾸지 않았다. 이후 가설 설명의 숫자 재생성을 출력 스키마에서 제한하고 전체 6개 질문을 다시 실행했다. 마지막 질문에 `９５`처럼 전각 숫자를 쓰는 사례가 있어 숫자 제약을 추가 보완하고 해당 질문만 다시 실행했다. 이 최신 결과와 나머지 5개 답변을 최종 코드로 대조한 것이 위 결과다.

## 검사와 한계

- 회귀 검사: `python -m unittest discover -s tests -q` — 80개 통과. HTTP/SSE·MCP 연결, 번호 누락·중복·위조, 원문 조치, 수치 비교와 재작성 제한을 포함한다.
- 범위: 이번 작업은 남아 있던 복합 진단 검수 보완이다. MCP 동시 실행·SSE 오류 처리·역할 및 진행 표시·LangSmith 평가·ADR 작업은 별도다.
- 현재 문서 파서는 번호별 절차가 한 줄인 매뉴얼 형식을 지원한다. 조치 원문 일치는 해당 조치의 운영 적절성까지 보장하지 않는다.
- 수치 검사는 명시적인 일부 표현과 알려진 알림 형식에 한정된다. 숫자를 한글로 풀어 쓴 표현 등 모든 의미 오류를 차단하는 검증기는 아니다.
- 가설의 적절성·확인 자료 선택은 여전히 모델 판단이다. 예를 들어 CPU와 네트워크 대역폭의 관계나 로그 누적과 디스크 부족의 인과 방향은 현재 자료만으로 확정할 수 없다. 검증 통과가 이 가설들을 입증한 것은 아니다. 자료 유형이 넓게 선택될 수 있고, 가설과 정상 설명의 세부 분류나 판정 이유가 항상 정확한 것은 아니다.
- 실제 운영 서버 데이터와 OpenAI API 호출은 검증하지 않았다. 실행 방법은 [평가 안내](README.md)를 따른다.
